# Security review BookNest

1. Пароли валидируются по длине и составу в `app/schemas.py`.
2. Пароли хешируются bcrypt через passlib в `app/security.py`; исходный пароль не сохраняется.
3. `UserRead` не содержит `password_hash`, все auth-ответы используют `response_model`.
4. Ошибка входа одинакова для неизвестного пользователя, неверного пароля и неактивной записи.
5. Access JWT содержит только `sub`, `role`, `type`, `iat`, `exp`.
6. Refresh JWT имеет отдельный `type` и срок до 7 дней; payload не содержит чувствительных данных.
7. Подпись JWT проверяется HS256; access-токен нельзя использовать как refresh.
8. `SECRET_KEY` обязателен в окружении и не имеет значения по умолчанию.
9. `.env` исключён из Git, а `.env.example` содержит только безопасные примеры.
10. `get_current_user` проверяет подпись токена и активность пользователя.
11. `require_librarian` защищает все операции изменения каталога на сервере.
12. Чужая выдача скрывается кодом 404 в `visible_loan`, предотвращая IDOR.
13. SQL строится SQLAlchemy с параметрами; пользовательский ввод не конкатенируется в SQL.
14. React не использует `dangerouslySetInnerHTML`; данные выводятся экранированным JSX.
15. CORS задаётся явным списком `CORS_ORIGINS`; `*` с credentials не используется.

Автоматические проверки прав находятся в `backend/tests/test_api_integration.py` и покрывают
гостя, читателя, библиотекаря, чужой объект, невалидные данные и конфликт доступности.
